# Personal OS → Public Website Publishing Contract

This document defines the boundary between the future private Personal OS and the public `kaize-wang.github.io` repository.

## Core rule

The public repository is an **output layer**, not the source of private work.

Private notes, tasks, AI conversations, unreleased research, internal links, and draft translations must remain in Personal OS. Only explicitly reviewed public material may be exported here.

## Localized content identity

Chinese and English versions of the same object share one `contentId`.

Example:

```yaml
contentId: paper-depth
lang: zh
sourceLanguage: zh
translationStatus: original
sourceRevision: "2026-08-08-03"
visibility: public
```

```yaml
contentId: paper-depth
lang: en
sourceLanguage: zh
translationStatus: reviewed
sourceRevision: "2026-08-08-03"
visibility: public
```

The source language may be either Chinese or English.

## Translation lifecycle

`translationStatus` has four states:

- `original`: human-authored source version
- `ai-draft`: generated by AI and not yet approved
- `reviewed`: localized version has been reviewed and can be published
- `outdated`: the source changed after this translation was created

When the source version changes, Personal OS should compare `sourceRevision`. Any localized version based on an older revision becomes `outdated` until regenerated and reviewed.

## Publication safety gate

The Astro public site emits a localized object only when both conditions are true:

1. `visibility === "public"`
2. `translationStatus` is `original` or `reviewed`

`ai-draft` and `outdated` versions are excluded even if visibility is accidentally changed to `public`.

## Intended Personal OS workflow

```text
Capture / write source
        ↓
Private object
        ↓
Develop and connect to projects / research
        ↓
Mark as draft
        ↓
Generate missing language with AI
        ↓
Review translation and terminology
        ↓
Preview Chinese + English public pages
        ↓
Approve publication
        ↓
Export reviewed Markdown / structured data
        ↓
GitHub commit / pull request
        ↓
Astro build
        ↓
GitHub Pages
```

## AI translation requirements

Personal OS should eventually maintain:

- a bilingual terminology glossary
- style profiles for academic pages, research notes, blogs, and CV content
- translation memory for previously approved phrases
- source/translation revision history
- diff preview before accepting AI changes
- one-click regeneration when a translation becomes outdated

AI generation must never imply publication approval.

## Public content types

The first supported exported object types are:

- Blog
- Project
- Research Note
- Publication

Later types may include public reading notes, datasets, talks, and selected timeline updates.

## URL stability

Existing public URLs should remain stable whenever possible. For example:

- `/blog/first-note/`
- `/blog/paper-depth/`
- `/blog/research-training-reflection/`
- `/research/`
- `/publications/`
- `/projects/`
- `/openings/`
- `/cv/`

English localized routes use the `/en/` prefix.
